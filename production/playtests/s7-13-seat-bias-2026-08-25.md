# The seat bias — root cause found

> **Follows**: `s7-12-round-cap-2026-08-25.md`, which exposed that P1 wins every close game
> **Date**: 2026-08-25 · **Story**: S7-13
> **Status**: ✅ **Root cause identified and proven by controlled experiment. Not yet fixed.**

---

## The finding, in one line

★★ **`Movement.reachable()` expands neighbours in a fixed N→E→S→W order, and the AI keeps the
first tile among equal-scoring candidates — so BFS enumeration order becomes a hidden
directional preference that decides matches.**

Changing that single line changes who wins:

| Neighbour order | Material advantage converts | Seat split (+1 cell, n=14) |
|---|---:|---:|
| **N→E→S→W** (shipped) | **7/14** | east wins **14/14** |
| N→W→S→E (probe) | **14/14** | **7/7 — balanced** |

With the shipped order the game is decided by which end of the map you start on. With the
probe order the extra Trooper wins every game it is given to, and the seats split evenly —
which is what a fair, deterministic game should look like.

## How it was narrowed down

Three candidate explanations, each eliminated by a controlled run rather than by reading code.

### 1. It is not the player index

| Handicap | Starts | P0 wins | P1 wins |
|---|---|---:|---:|
| +0 mirror | P0 | 1 | 3 |
| +0 mirror | P1 | 1 | 3 |

★ **Identical.** Forcing the starting seat changes nothing in the mirror cell.

### 2. It is not turn order

Same table — P1 wins 3/4 whether it moves first or second. There *is* a small first-mover
component in the +1 cell (P0 takes 4 games when it moves second, 0 when it moves first), but it
is secondary and cannot explain a 14/0 result.

### 3. It IS the board position

Swapping which HQ each seat owns moves the advantage with the position:

| +1 cell, P0 always starts | P0 wins | P1 wins |
|---|---:|---:|
| Normal — P0 west, P1 east | 0 | **14** |
| Swapped — P0 east, P1 west | **10** | 4 |

> ### ⚠ The first version of this experiment was invalid, and it is worth recording why
> `_bonus_tile` and the mirror seeding derived their placement from the `HQ_A`/`HQ_B`
> **constants** rather than from the HQ each seat actually owned. Under `--swap-hqs` the
> favoured player's bonus Troopers therefore spawned **beside the enemy base**. The run
> produced a clean, confident, completely wrong attribution. Both now take the owning HQ as a
> parameter, and the un-swapped path was re-verified to reproduce the original numbers exactly
> (P0 0 / P1 14) before the swapped result was believed.

## The mechanism

`Movement._neighbors_in_fixed_order` expands `[UP, RIGHT, DOWN, LEFT]`. Its own doc comment
explains the fixed order exists **for determinism** — *"Determinism (the tie-break AC) depends
on this order being self-contained here"* — and it does deliver that. What it also delivers,
unintentionally, is a **direction**.

`reachable()` returns tiles in that expansion order. The AI's advance fold then does:

```gdscript
elif dist_after == adv_dist_after and _is_better(score, ...):
```

`_is_better` requires *strictly* better to replace, so **among tiles that tie on distance and
score, the first one enumerated wins** — and East is always enumerated before West.

★ The consequence is not symmetric between the two players. For the **west** player, the
easterly tile is *toward* the enemy; for the **east** player, it is *back toward its own base*.
So the same rule pulls one side forward into the open and lets the other consolidate at home —
and in a deterministic game with no fog, the side that commits first loses the exchange.

⇒ **This is the same phenomenon S5-04 recorded from the turn-order angle** — *"the player who
moves first loses every mirror"* — seen from its actual cause. It was never really about moving
first; it was about being pulled forward.

## ⚠ What this invalidates

- **S6-06's "material advantage converts 18/18"** is not a measure of the economy or the
  combat model. Under the shipped order that figure is **7/14** in a fair-start batch; the 18/18
  was the east seat winning its own games plus the round cap truncating the rest.
- **Every close-game measurement taken so far** — S7-09's skill floor, S7-10's exchange rate —
  ran with this bias present. Their *relative* comparisons hold (both arms measured under
  identical conditions) but no absolute claim about balance survives.

## ⛔ Not fixed here, and why

The fix is **not** "reverse the order" — N→W→S→E is just a different arbitrary direction that
happens to test well on this map, and would bias the other way on a map laid out north–south.

The correct fix is to make the AI's tie-break **mirror-invariant**: when candidates tie on
distance and score, decide between them on something that does not depend on enumeration order
(distance to the enemy HQ, then to the own HQ, then a deterministic final key). That is a
behavioural change to the AI, it will move every number recorded to date, and it wants doing
deliberately rather than at the end of a long session.

★ **A first-turn AP reduction does not address this.** That is the standard remedy for a
first-*mover* advantage, and the mirror cell shows turn order contributes nothing here — the
result is identical whichever seat starts. Worse, the small turn-order component that does exist
runs the *opposite* way: moving first is a slight **disadvantage** (P0 wins 4 when it moves
second, 0 when it moves first), so cutting the first player's AP would deepen the real problem
rather than offset it.

## Harness changes made for this investigation

- `--start-player=N` — force which seat moves first, for every game in the batch.
- `--swap-hqs` — swap which HQ each seat owns.
- `_bonus_tile` / mirror seeding now take the **owning** HQ, fixing the confound above.

Suite **1253/1253**, 0 orphans. No production behaviour was changed by this story.
