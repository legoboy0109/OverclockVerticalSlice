### 5. ⚠ Advisory — one non-fatal warning on slice boot

```
WARNING: Nodes with non-equal opposite anchors will have their size overridden after _ready().
     at: _set_size (scene/gui/control.cpp:1484)
     [0] fill_viewport  (src/ui/menu/menu_style.gd:120)
     [1] _ready         (src/ui/pause_menu/pause_menu.gd:58)
```

**Cause.** `MenuStyle.fill_viewport()` sets `PRESET_FULL_RECT` (anchors 0,0→1,1 — "non-equal
opposite") and *then* assigns `size` explicitly. Godot warns that the explicit size will be
overridden after `_ready()` by the anchor solve.

**Assessed as cosmetic, and here is the evidence rather than the assumption:** `05-paused.png`
shows the overlay correctly filling the viewport with the panel centred. The anchor solve
produces the right result, so the explicit assignment being discarded costs nothing.

★ **But it is worth leaving in the record rather than silently suppressing**, because this exact
code path is the one whose failure mode has already bitten the project **twice** (S6-23, S6-24) —
a zero-size Control whose symptoms look like anything but a sizing bug: a scrim that covers
nothing, and a `CenterContainer` centring on the origin so the panel lands in the top-left corner.
The explicit `size` assignment is the belt to the anchors' braces. **If it is ever removed to
silence this warning, the belt goes with it** — and the frame above is the only thing currently
proving the braces hold.

⇒ Recorded, not fixed. Tidy-up candidate: keep the assignment and `set_deferred("size", …)`, or
drop it and add a test asserting non-zero size after `_ready()`.
